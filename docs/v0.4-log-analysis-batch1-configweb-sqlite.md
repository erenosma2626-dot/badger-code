### Trial 4: `sqlite-with-gcov` — `EX92BKr` (Reward: 0.0 — BAŞARISIZ)

- **Dosya:** `starter/jobs/2026-09-15__01-08-59/sqlite-with-gcov__EX92BKr/result.json`
- **Sonuç:** Reward `0.0`, Tur: `18` (39 mesaj), Bitiş: `stuck_loop_detected`, Doğrulama Durumu: `not_applicable`
- **Verifier Çıktısı (`verifier/test-stdout.txt`):**
  - `FileNotFoundError: [Errno 2] No such file or directory: 'sqlite3'`
  - `3 failed in 0.08s`

#### Kök Neden: v0.4 Mekanizma C'de Kritik Yanlış Pozitif (Fatal False Positive)
1. **İlerleme ve Doğru Teşhis:**
   Agent vendored tar.gz arşivini açtı, eksik paketleri (`build-essential tcl8.6 tcl8.6-dev`) apt lock'larını temizleyerek kurdu. SQLite'ın autosetup betiğinin `--enable-coverage` bayrağını tanımadığını fark etti.
2. **Turn 12'de Gelen Hedef Nudge'ı:**
   Turn 10 ve Turn 12'de `./configure` hata verince 3. verimsiz denemede `TARGET_STUCK_LOOP_MESSAGE` tetiklendi ve `stuck_nudged = True` oldu.
3. **Sorunun Çözülmesi (Turn 18):**
   Agent `Makefile.in` ve `config.log`'u okuyup grep yaptıktan sonra sorunu tam olarak çözdü ve Turn 18'de (Msg 36) şu kusursuz komutu çalıştırdı:
   ```bash
   cd /app/sqlite && ./configure --disable-shared --enable-static CFLAGS='-fprofile-arcs -ftest-coverage'
   ```
   **Bu komut `exit_code: 0` ile tamamlandı, `Makefile` ve `sqlite3.pc` üretildi!** Agent bir tur sonra `make && make install` yapıp görevi bitirecekti (v0.3'teki 1.0 alan trial ile birebir aynı akış).
4. **Kritik Yanlış Pozitif: Guardrail Başarılı Komutta Agent'ı Öldürdü:**
   `starter/agent/tools.py` içindeki `is_unproductive_attempt()` fonksiyonu şu şekildedir:
   ```python
   def is_unproductive_attempt(exit_code: int | None, output_text: str) -> bool:
       if exit_code not in (0, None):
           return True
       lowered = output_text.lower()
       return any(kw in lowered for kw in _UNPRODUCTIVE_KEYWORDS)
   ```
   Burada `_UNPRODUCTIVE_KEYWORDS` listesinde `"not found"` yer almaktadır.
   Autoconf / configure betikleri sistem özelliklerini tararken rutin olarak `...not found` çıktısı verir. Turn 18'deki `./configure` çıktısında şu satırlar yer alıyordu:
   - `Checking for localtime_s...not found` (Windows C runtime fonksiyonu Linux'ta aranıyor)
   - `Emscripten SDK? not found`
   Çıktıda `"not found"` geçtiği için `is_unproductive_attempt(0, output)` fonksiyonu **`True` döndürdü!**
   `target_attempt_counts['./configure']` 4'e çıktı (>=3) ve `stuck_nudged` Turn 12'den beri True olduğu için `agent.py` ajanı Turn 18'de acımasızca **`stuck_loop_detected` diyerek erken sonlandırdı!**

#### Kanıt (Log Alıntıları)
- **Turn 18 (Msg 36) — Başarılı komut ve sıfır hata kodu:**
  ```json
  {"tool": "terminal_exec", "command": "cd /app/sqlite && ./configure --disable-shared --enable-static CFLAGS='-fprofile-arcs -ftest-coverage'"}
  ```
  *Receipt:* `"exit_code": 0`, `"changed_paths": ["./sqlite_cfg.h", "./Makefile", "./conftest__.gcno", "./config.log", "./sqlite3.pc"]`
- **Turn 18 stdout'undaki tuzak satır:**
  `Checking for localtime_s...not found`
- **`trial.log` Kanıtı:**
  `turn 12: stuck loop detected (3 unproductive attempts against target './configure'), sending nudge`
  `turn 18: stuck loop repeated after nudge, terminating`

#### Kategori ve Güven
- **Kategori:** `altyapı/guardrail arızası (yanlış pozitif stuck-loop ile erken sonlandırma / false positive termination)` (YENİ KATEGORİ)
- **Güven:** **Yüksek.** Kod ve log verisi ile %100 kanıtlanmıştır.

   v0.3'te StructuredToolAgent şartnamedeki port 8080'i "kullanıcı muhtemelen port 80 demek istedi" diyerek reddetmiş ve hiç çalıştırmadığı bir curl komutunu kanıt olarak sunmuştu. v0.4'teki 3 trial'ın **3'ü de port 8080'i hedeflemiş** ve hiçbirinde hayali kanıt üretilmemiştir.
2. **Mekanizma C'nin Kanıtlanmış Başarısı (GERÇEK İYİLEŞME):**
   Trial 3, v0.4'ün hedef-bazlı stuck-loop mekanizmasının (`TARGET_STUCK_LOOP_MESSAGE`) kör bir curl döngüsünü kırarak ajanı konfigürasyon düzeltmesine ve `service apache2 reload` çözümüne yönlendirdiğini açıkça göstermektedir. Bu doğrudan v0.4 mekanizmasının eseridir.
3. **Kalan Varyansın Kaynağı:**
   Trial 2 ile Trial 3 arasındaki tek fark, Apache daemon'ının container ortamındaki garip `service apache2 restart` arızasıdır. Trial 1 doğrudan Nginx seçtiği için bu engele hiç takılmamıştır; Trial 3 `reload` alternatifini bularak aşmıştır; Trial 2 ise `restart` ısrarı yüzünden 64. turda stuck-loop tarafından kesilmiştir.
4. **Hüküm:** **2/3 başarı GERÇEK BİR İYİLEŞMEDİR.** Şartname uyumu ve doğrulama disiplini kalıcı olarak düzelmiştir.

### 2. Doğrulama Kapısı (§2.1) — PASİF / GEREKMEDİ

### 3. Stuck-Loop Genişletmesi (§1.1-2 / §2.3) — İKİ TARAFLI KILIÇ (1 Kurtarma, 1 Haklı Kesme, 1 Kritik Yanlış Pozitif)
- **Başarı (Trial 3):** `http://localhost:8080/hello.html` hedefindeki 3. başarısız denemede nudge atarak ajanı kurtardı.
- **Haklı Kesme (Trial 2):** Sonsuz Apache hata ayıklama döngüsünü 64. turda kesti (100 tur limitine gitmesini önledi).
- **Kritik Kritik Yanlış Pozitif / Yanlış Pozitif (Trial 4):** `is_unproductive_attempt()` fonksiyonunda yer alan `"not found"` anahtar kelimesi, `./configure` betiğinin normal çıktısında yer alan `Checking for localtime_s...not found` satırı yüzünden exit code 0 olan başarılı komutu "verimsiz" saydı ve tam çözüme ulaşmış ajanı 18. turda erken sonlandırdı!
- **Global Latch Zaafı (Trial 5 & 4):** `stuck_nudged` bayrağı bir kez True olunca, oturum boyunca sıfırlanmıyor. Ajan strateji veya hedef değiştirse bile, daha sonra herhangi bir hedefte 3 verimsiz deneme olduğunda ikinci bir şans verilmeden doğrudan sert sonlandırma yapılıyor.

### 4. `verification_status` İzleme (§1.1-1) — YANLIŞ POZİTİF ZAAFI
- Trial 6'da görüldüğü gibi, StructuredToolAgent'ta `terminal_exec` için test/edit ayrımı bulunmadığından, `write_file` sonrasında çalıştırılan herhangi bir `chmod +x` gibi idari komut (exit code 0) `pending_verification` bayrağını temizlemekte ve verifier başarısız olsa bile metadata'ya `verification_status: passed` yazdırmaktadır.

## 5. Önerilen Düzeltmeler (Lead / Planlama İçin)

1. **`is_unproductive_attempt()` Acil Revizyonu:**
   `exit_code == 0` olduğunda `_UNPRODUCTIVE_KEYWORDS` kontrolü **yalnızca grep/find/cat gibi arama/okuma araçlarına** uygulanmalı; `./configure`, `make`, `python3`, `bash` gibi derleme/çalıştırma komutlarında exit_code 0 ise komut kesinlikle başarılı (productive) sayılmalıdır.
2. **`stuck_nudged` Bayrağının Hedef-Bazlı (Per-Target) Olması:**
   Ajan `./configure` için nudge aldıktan sonra hedef değiştirip bir dosyayı okumaya başladığında, eski nudge yüzünden anında hemen sonlandırılmamalıdir. Nudge bayrağı hedef bazında (`target_nudged: set[str]`) tutulmalıdır.
3. **`structured_tools.read_file` Hata Yönetimi:**
   Dosya bulunamadığında `decode failed: Incorrect padding` ve exit 0 dönmesi engellenmeli; açıkça `exit_code: 1` ve `error: "No such file or directory"` döndürülmelidir.
4. **`verification_status` Test Sınıflandırması:**
   `terminal_exec` receipt'inde sadece `exit_code == 0` yeterli olmamalı; komutun en azından `chmod`, `chown`, `mkdir`, `touch` gibi non-test komutları olmadığı doğrulanmalıdır.
